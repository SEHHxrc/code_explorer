# 静态安全证据盲态对照实验页面

新配对使用 `static-security-v14-review-ledger`：初始路径摘要、排序及调查轮次不变，两组共用发现台账与六类覆盖，报告计数由后台按状态生成。页面显示四段报告，并可折叠查看最终台账；内容全部转义，不用 HTML 注入。每批生成后立即显示，失败/取消保留已输出批次；历史从原事件恢复，不调用模型补写。

共同报告版本 v6 允许每次运行最多一次格式重提交（不新增调查或证据）。若指标中记录了格式拒绝，页面提示重提交次数；首次失败原文、结束状态及全部成本保留。格式完整不证明语义正确，也不能把恢复成功当成首次生成成功；旧 v5 记录不补写、不与新条件混算。

`ExperimentComparison.vue` 比较“静态安全证据 + 原始文件”与“仅原始文件”的安全分析答案。创建后隐藏组别标签，展示左右答案、供应商真实输入/输出 Token、用量完整/部分/不可用状态、终止原因与回答完整性；字符估算独立标注，不替代真实用量。只有两组都成功、回答完整且运行条件一致才显示评分；失败、取消、截断或完整性未知不算有效效果对比，质量警告由后端提供。提交评分后揭盲。新 `security_evidence` 与旧 `graph` 历史分别显示，不能混合统计。

两组要求同一四段简洁报告，渲染时隐藏末尾 `SECURITY_REPORT_END` 检查标记，不修改后端原始答案。界面所说完整仅是正常终止和报告结构通过，不代表全部漏洞已审计。历史记录缺失字段显示未知，不回填。

## 入口与依赖

`BlindReviewResult.vue` 在打开已评分历史及刚提交评分后，独立显示已保存偏好、四项分数和备注；
揭盲不会再隐藏结果。缺失历史分数显示未记录，不补成默认 3 分。历史列表直接显示左右/相当偏好，
两次试验并排窗口复用同一只读组件。所有备注按文本转义，不自动修改旧评分或代替人工核验。

通过显式脚本创建的 `static-security-v8-full-source` 记录同样可在历史查看，显示独立条件提示和
“完整源码，零工具单次报告”模式。当前网页为 v14，累计配额为 v15，完整源码为 v16，均有台账协议提示，不与旧条件混算。

统计分别显示墙钟耗时、剔除前置拒绝/退避后的耗时、剔除量、供应商真实用量和按冻结声明核算的模型总量。
只有匹配当前端点/模型的确认声明才允许 429/503 零模型 Token；原始 usage 状态仍展示，未知成本尝试不补零。
历史缺少调整计时显示未知，不以当前策略重算旧记录。

组件接收当前 `projectId`，通过 `services/experimentApi.js` 调用创建与评审接口，并消费比较 SSE 快照。它依赖后端 `experiments` 模块保证两组使用相同模型和步骤预算。

> **临时对照组边界：** 重复试验确认静态安全证据更优并结束对照实验后，应按 `../../../../docs/EXPERIMENT_PROTOCOL.md` 清理对照分支，而不是保留为长期产品模式。
