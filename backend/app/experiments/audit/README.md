# 实验可见内容审计模块

本模块属于实验域，不参与静态扫描、污点传播或模型安全结论生成。只对启用本版本后创建的配对收集审计，不改写或补写旧实验。普通 Agent 不启用该审计。

新报告的原始可见输出为发现台账 JSON，审计不将其替换为生成的 Markdown。台账及生成报告另外通过运行事件保存，结构/状态冲突失败也保留原响应。
`execution_policy.network_accounting` 冻结当前端点/模型的管理员执行前拒绝声明。仅匹配声明且实际收到 HTTP 429/503 的失败尝试可另计零模型 Token；不是供应商报告的零 usage。
对应失败请求的实测耗时与其实际退避单列，取消中的等待只计已发生部分，不重复扣除。未知超时、连接中断和本地解析失败不套用。
旧审计缺少声明不回填，供应商原 usage 和墙钟时间不改写；派生指标由 `experiments.metrics` 同时输出原始/按声明核算口径。

## 文件与入口

| 文件/类 | 功能与依赖 |
| --- | --- |
| `policy.py` / `AuditLimits` | 有界配额、规范 JSON 哈希、可见字段允许列表和脱敏。依赖公共敏感文本过滤及配置读取。 |
| `repository.py` / `AuditRepository` | 审计数据库读写、所有者校验、同事务预留配额、终态封存与过期清理。依赖两张审计表。 |
| `recorder.py` / `AuditRecorder` | 源码/产物指纹、发送规划、实际 HTTP 尝试及可见回复，收集源码展示范围。实现 `llm/observation.py` 的观察协议。 |

`ExperimentRepository.create_pair()` 在同一事务中为两组预留相同运行配额，并冻结共同提示词、工具 Schema、报告版本以及阶段版本/调查轮次/最终报告模式的契约哈希。`AgentQueueWorker` 仅为已有预留会话创建记录器；`AgentRunManager` 在模型调用前建立指纹、绑定上下文隔离的 HTTP 观察器。API 与 Worker 契约不一致时，请求发送前失败，避免混版实验。`asyncio.to_thread` 继承当前观察器，并发两组不共享观察器。阶段说明保存在实际消息中，策略保存在 manifest；失败不自动重写状态或改变模式。

## 保存的内容与边界

- `manifest`：当前清理后的项目工作目录中各文件 SHA-256、字节数和可核对行数，完整静态产物哈希，共同提示词内容/版本/哈希及工具 Schema 哈希。不是原始 ZIP 的哈希，也不是历史输入还原。哈希不能恢复源码或证明结论正确。
- 新运行的 `experiment.snapshot` 事件只复用 manifest 中脱敏共同提示词和指纹/策略，不含文件清单、源码、工具或实际请求正文；供普通所有者历史对比，不进入模型输入，也不随完整审计正文过期删除。旧记录不回填。历史接口只投影允许字段，不绕过完整审计管理员权限。
- `planned_request` 与 `request` 分开：前者是编排规划，后者是传输层准备实际发送的每次 HTTP 尝试；包括脱敏消息、工具定义、生成参数、精确序列化字节数/哈希。重试分别记录，不把 Provider 测试替身当成真实 HTTP。
- `response` 与 `visible_turn`：供应商可见消息、工具调用、结束原因、usage，以及适配器规范化结果。认证头与 URL 从不进入观察接口；隐藏推理正文、加密续接状态不保存。
- 新 `response.channel_sizes` 仅记录 Chat 消息中的文本通道是否存在、字符数和消息字节数，用于区分可见正文为空与其他通道存在；不保存隐藏正文，也不把字符数换算为供应商推理 Token。旧记录不补写。
- 新 `response.transport` / `request_failed.transport` 记录每次真实 HTTP 尝试的 UTC 开始/结束时间、超时参数、等待响应头与读取完整响应体的耗时、字节数和失败阶段。错误只保存类型、数字错误码及经脱敏的允许供应商字段；HTTP 错误正文仅计量大小/格式/读取失败，不保存正文。等待响应头阶段包含连接、发送及服务端等待，不能进一步冒称“已确认代理故障”或“已确认模型推理超时”；socket 超时也不是完整请求的总时长上限。旧记录不补写。
- `citations`：按成功响应对应的发送内容建立源码展示账本，核对路径、行号和展示范围。失败请求不当作已看到；最后一轮省略早期源码时提示警告。它不证明引用支持断言，`semantic_coverage=not_proven` 不变。

常见密钥、私钥及当前配置的模型 API Key 会被脱敏，但这不是通用 DLP 保证。数据库正文仍含项目敏感源码且未额外加密，应限制服务器数据库/备份权限。允许列表投影不是原始网络报文原样存储；原始报文仅保留哈希，不能事后反推秘密或隐藏状态。

用量只累计供应商确实报告的成功响应，不代表账单。当审计的实际 HTTP 尝试数大于有输入/输出用量的响应数时，指标标记为部分用量，返回 `http_attempts` 和 `unreported_http_attempts`；成功重试不能把超时尝试的未知消耗算作零。指标只读派生，不回写历史事件；缺少审计尝试数时保持未知。

`retry_wait` 记录失败尝试后的等待策略版本、逻辑步骤、失败尝试序号、HTTP 状态、计划/实际等待秒数和是否完成；取消时仍标为未完成。等待不是 HTTP 尝试，不累加请求数或用量。当前策略为 `exponential-jitter-v2`，两组共同执行策略记录 `http_retry_policy`，完整源码试验的模型配置指纹也包含它；不得直接与 `bounded-rate-limit-v1` 等历史策略混算耗时和成本，旧记录不补写。指数窗口、随机区间及 `Retry-After` 下限详见 LLM 模块 README。

## 配额、清理与删除

默认单条 4 MiB、单运行 32 MiB、全体 1 GiB（JSON 负载计量），未盲评且已终止的运行保留 30 天；参数在 `backend/.env.example`。这是负载配额而非 SQLite 物理文件硬上限；删除正文后数据库页可能留作复用。超限不静默截断，明确停止本次运行。快照限制为 10000 文件、256 MiB、30 秒；变化的源码或不可完整读取的快照停止请求。

Worker 的维护循环调用 `cleanup_expired()`，仅清理过期、未保护、运行终态的审计正文，保留过期标记和原实验事件。完成盲评后记录受保护、不自动过期，仍占总配额。删除项目时，审计、实验、Agent 等记录由 `ProjectDeletionRepository` 在同一数据库事务中删除，失败一起回滚。该策略不修改旧实验记录。

## 受控查看

`GET /api/experiments/comparisons/{comparison_id}/audit/{left|right}` 需要项目所有者身份及 `X-Audit-Token`，并满足：

1. `EXPERIMENT_AUDIT_READ_ENABLED=1`，管理员设置独立的至少 32 字符口令。
2. 后端看到的直接客户端 IP 属于本机回环；不信任转发 IP 头。公开反向代理不可绕过所有者与口令要求。
3. 有效实验先完成盲评；无效终态实验可显式传 `acknowledge_unblind=true`，仅用于被排除试验的诊断。

前端“查看脱敏审计（管理员）”按次询问口令，不保存口令，使用转义纯文本展示。普通 SSE/指标只返回状态和机械警告，不能泄露盲态组别或审计正文。读取默认关闭不影响自动收集。旧实验无审计则返回不可用，不按当前代码重建。对照组的静态产物仅在审计中计算指纹，不进入模型上下文。
