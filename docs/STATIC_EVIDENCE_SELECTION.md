### 初始摘要包含什么

主体只有三类路径/线索，ID 始终使用原候选或事实 ID：

| 优先级 | kind | 含义 |
| --- | --- | --- |
| 1 | `propagation_path` | 有原产物值流步骤的已建模传播；不是运行时可行或可利用证明。 |
| 2 | `structural_lead` | 有调用边的结构线索；不证明值进入了危险参数，缺失边明确标为 incomplete。 |
| 3 | `operation_lead` | 单点安全敏感操作，或只有同函数共现/未建立连接的来源关联；不生成传播箭头。 |

同级先覆盖不同目标位置/规则，再按显式 Shell 上下文、规则等级和位置稳定排序。优先级表示核验顺序，
不是漏洞概率或最终风险等级；不从路径名断言测试/CI 不重要或部署可达。

每条包含 ID、类别/规则、端点位置及现有参数角色、关系类型、优先理由、置信度、may 状态和不完整标记。
顶层只保留版本、快照、条目/类型/省略计数、必要语义和 `_coverage` 详情入口。
初始不列出全局统计、规则说明、完整局限、Guard/Sanitizer、孤立 Source、源码正文、图、Manifest 或 Repo Map。
两组的共同指令/文件审查范围不是静态摘要的一部分，仍按对应实验协议提供。

每条先尝试交付全部原有步骤，再继续下一条；整条放不下才降为明确标记的定位，最多八条目录。
因此低优先级端点不会先挤掉高优先级路径的已有步骤。`inline_all_retained_steps`
只表示所保存序列全部交付，不代表项目全部路径已解析；保留每一步顺序、行列、变量 uses/defines、may/must 与来源。
长路径使用 `sequence_delivery=detail_only`，不抽样首尾，可按原 ID 分页读 flow；
极长端点使用 `locators_delivery=detail_only` 及事实引用，可先读 overview。
未展开与未解析不同；零条目不证明安全。路径不完整、缺引用或越出固定审查范围时，不伪装为完整链。

## 历史：2026-10-15 时的三条交付路径

完整产物是 `SecurityEvidencePack`，不是模型输入本身。它保存入口、Source/Sink/Guard/Sanitizer、
结构调用边、数据流、共享片段、候选 ID 引用、覆盖和局限。

| 消费路径 | 选择入口 | 交付方式 |
| --- | --- | --- |
| 普通 Agent / 安全证据接口 | `SecurityEvidencePromptBuilder` | 1.4 紧凑 JSON、共享片段表。 |
| 网页默认 v7 按需实验 | `SecurityEvidenceCatalog` | 初始目录、按 ID 查详情、分批报告。 |
| 最近的 v8/v9 补充实验 | `full_source.bounded_facts` | 一次性有界事实，无静态详情工具；v9 另有累计源码读取配额。 |

因此，1.4 已完成的片段去重、v7 的按需查询，**不能当成 v9 实际发出的输入**。
最近一次负收益结论继续归属于实际执行的 v9 方案，原报告、失败、用量与评审不改写。

```text

    ↓

    ↓

    ↓
```

## 根因：不是源码片段去重没完成

旧 `bounded_facts` 按文件路径、行号、ID 排序，先填 facts，剩余空间才放两端均已保留的候选关联。
这是一种稳定但与调查价值无关的选择方式。前面文件的普通条件、变换匹配会挤掉后面实现中的 Sink；
关联端点未选中时，即使全量产物有路径，也不会被交付。

audio2sheet 的实际旧输入共 14 条：**11 个 Guard、3 个 basename 匹配，Source/Sink 均为 0，关联为 0**。
原产物却有 17 个 Sink、11 个候选、1 条函数内数据流。BasicPitch 的 `os.rename:63` 也已存在，
并不是“扫描器完全不知道写入实现”，而是投影时没有选中。

另一个表达问题是：旧关联仅交付若干概括字段，不交付完整有序流步骤；端点共现、结构可达和变量传播
对导航的帮助不同，不能一概称为已验证调用链。规则把 API 标为 sanitizer，也不证明它防护了对应危险值。

这些缺陷可以解释为什么当前输入缺少有效导航，但不能单凭离线检查量化它们各自造成多少模型质量差异。

## 新选择器：`security-navigation-v1`

入口：

```python
selector = SecurityEvidenceSelector(raw_pack, paths=set(fixed_relative_paths))
navigation = selector.build(max_bytes=7676)
text = encode_navigation(navigation)
```

输入为已保存产物和固定审查文件集合，输出为自包含紧凑 JSON；不访问源码、模型或网络，不重建图。
实现属于 `services/security_analysis`；实验层只消费它，不再另写一份扫描/传播算法。

### 选择规则

1. 以同类别、同文件、同函数中的 Sink 为实现导航组。同组不等于同根因或已连通数据流。
2. 显式 Shell 上下文、已有静态值流、规则影响等级决定调查顺序；同级倾向保留多操作实现，
   再按位置稳定排序，并让不同实现文件先获得导航机会。这个优先级不是漏洞概率评分。
3. 保留危险操作定位时，按现有关系及首个相关条件的实际投影大小预留详情空间，最多预留预算的 40%。
   不采用“先用普通条件填满，再碰运气放关系”的方式。
4. 已选操作的关系全局优先交付已有值流，其次结构关联；不能让前一个 Shell 组的共现关联挤掉后一个组的实际值流。
5. 再补已交付关系的相关条件/变换定位，最后补未配对 Source。没有 Sink 时给真实 Source 和覆盖，
   不用大量无关 `if` 填满输入；不虚构不存在的风险链。

这里仍是启发式导航，不保证所有高价值实现都入选，也没有引入针对 AES/audio2sheet 的文件名或答案清单。
完整原产物留在服务器；交付省略与静态分析自身缺失必须分开解释。

### 表达与边界

- `files` 为共享文件表；`nodes` 以原始事实 ID 保存规则角色、API 名、符号、行列、信任分类和必要参数上下文。
- `cards` 引用 Sink 组、关系和条件。`unlinked` 表示原产物没有该操作的候选链，
  `not_delivered` 表示存在候选但本次未交付；`some_delivered/all_delivered` 仅描述已有候选的交付数量，
  不代表分析完整、运行可达或漏洞已确认。省略的空字段默认值写在 `semantics.cards` 中。
- `links.claim` 区分函数内/跨函数数据流、结构可达、同函数规则共现、路径未知或引用缺失。
  不把零调用边的同函数匹配伪装成数据流。
- 值流保留**全部原有有序步骤**的路径、行列、输入/输出名字、must/may 和来源；表达式正文明确未交付。
  整条关系超预算则整条省略，不抽取首尾假装链路完整；存在的截断、未解析、前提和局限继续保留。
- 相同解析局限正文只在关系的 `notes` 中保存一次；候选 `limitations` 和流 `unresolved` 分别保留索引，
  可还原原归属和顺序，不混为同一个字段。
- Guard 仅为条件定位；Sanitizer 仅为变换规则匹配。没有证明“同一个值、适用危险上下文、发生在操作之前”。
  信任类别与参数角色也来自原规则，尤其不能把框架注入对象直接当成攻击者控制值。
- `analysis.coverage` 是原扫描统计，**不是本次交付覆盖率**；`omitted` 单独给出事实、类型、候选、范围外及缺失端点计数。
  无候选、无链、无检出均不能证明安全。
- 完整图、Repo Map、Manifest 概述和生成命令不进入本输入；源码仍须通过两组相同原始文件工具核实。

## 未被本轮修复的上游问题

这次专门隔离交付因素，没有重扫或更改规则/污点算法。仍须明确以下独立缺陷：

- **提取层**：框架注入对象可能被当作 HTTP Source；按 `.replace` 名称匹配文件操作可能混入字符串替换；
  `os.rename` 参数角色目前未完整表示目标路径。交付参数角色不等于完成语义验证。
- **传播/安全含义层**：`ProgramGraphSecurityFlowAnalyzer._sanitizer_nodes` 对规则标为 `result_role=sanitized`
  的调用节点执行传播阻断，尚未按具体 Sink 上下文验证有效性；可能造成漏链，不能简单解释为防护成立。

  本轮只给真实操作定位，**没有生成或猜测新的 HTTP→危险实现链**。
