# 静态安全分析覆盖清单

## 评价口径

### 当前增量：有界路径变体和外部 API 建议接口（2026-10-26，证据包 2.10）

- 初始摘要为 `security-path-summary-v3-variants`，同一端点族的不同值边/调用/结构路线分别交付。
  不因第一条 SAT 停止，不在服务层折叠为一个 dataflow；每族默认 8 条并保留独立 ID。
- 公共 ValuePathSearch 复用最终值图并缓存邻接/反向可达性，不重复 AST 或自研第二套传播。
  同步参数、返回和既有值边界均支持不同局部路线；结构线索也可保留非最短调用路线。
- 每 Source 跨过程默认 256 状态；局部/结构查询默认 2048 状态；超限和循环边界显式报告。
  完整 CFG 分支、循环、递归和对象/工厂摘要内部变体仍不穷举，不能宣称全路径覆盖。
- Go 正则 Guard 对准第二实参，仍不把观察当防护证明。未知 API 保留实参和有界已知前缀。
- LLM 知识来源只提供逐返回分量的待核验建议；无数据库、无自动启用、不进入纯静态产物，
  不自动净化或注册规则。单聚合与原生多返回沿用不同 ABI 槽位，数据依赖与过滤效果分别描述。
- 本轮不重跑真实模型或大项目，不改 .env/旧实验；新生成的证据/摘要不能与旧输入条件混算。

以下章节按历史阶段保留；当前能力在其原有限定范围上叠加本节，不将旧实验回填为新版能力。

对象能力按阶段记录，旧节中的“本轮未支持”指对应历史阶段；当前组合范围与限制以
ProgramGraph 1.20 公共链路闭合及其明确局限为准，不把旧实验回填成新版能力。

### 当前新增：收紧范围后的动态键与最小集合效果（ProgramGraph 1.17）

Python/Java/Go/JS/TS 的公共选择器仅解释局部字面量、名称赋值、条件选择与分支合并。
唯一常量精确读写，最多 8 个候选保留 may，未知键使用独立摘要槽；字符串 `"?"` 不等于未知键。
未知键的值读取合并同一分配的可能元素，键本身可控不自动使全部元素受污。有限/未知写是 weak_update，
不能清除旧内容；后续确定固定键覆盖仍切断该元素旧值。摘要跨函数读写复用原对象参数接口。
动态键字面量也经同一语法/求值机制接入，未知引用更新不沿用旧子对象的唯一身份。

新增 CollectionEffectProvider 接口，只用 Python 局部字面量原生 list（及已确认直接别名）的单次 append
完成正反例：追加值可到达对应固定元素，旧元素隔离，追加返回 None 不作为元素内容。

切片/删除/重排/迭代与其他语言集合变更仅留效果契约，不列为已支持。

普通跨过程预算默认 4→8，仍记录到界；结构路径默认 6、工厂快照转发默认 4 保持独立。

### 前一阶段：固定集合元素（ProgramGraph 1.16）

“容器”在此指集合数据结构，不是 Docker。以下是实际落地的有界范围，不是完整语言覆盖：

| 能力 | 范围 |
| --- | --- |
| 直接分配 | Python dict/list/tuple、JS/TS object/array、Java 数组初始化、Go map/slice/固定数组字面量。 |
| 固定元素 | 字符串 key/整数 index；Python 整数和字符串不混合，JS 按属性键归一；键中点号、数组空洞和同键覆盖保留语义。Python 已知完整序列支持负下标。 |
| 引用和值复制 | 同一集合别名共享元素；不同分配、相邻元素及重绑定隔离。Go map/slice 共享，固定数组复制/值参数不写回原数组。 |
| 跨函数 | 既有唯一项目调用的逐元素入口与正常出口写回；新集合/静态内部成员工厂返回复用快照；所有正常出口返回同一已绑定外部引用时保留原分配。 |
| 混合组合 | 对象字段保存集合、集合元素保存已知对象、静态嵌套元素沿同一引用环境逐跳查询。 |
| 证据 | 原始路径/行列、别名赋值、已有调用关系、分配 ID 与按候选 ID 分页保持；不把私有堆或生成操作当源码事实。 |

CollectionElementSlot 和 ObjectFieldSlot 分开建模，旧 1.0～1.15 图读取兼容但不自动补造新分配。

仍未覆盖动态下标/切片、可变大小与迭代、Java Map/List 方法、各种集合构造器/第三方库、C/C++ 数组指针

## 此前传播正确性整改（证据包 2.5 / ProgramGraph 1.2）

- FastAPI 按规范化注解排除 BackgroundTasks/Response，不按名字子串误删真实请求模型。

  `result = sink(value)` 核实真正的 value 实参；DOM 属性写入仍核实写出的属性，不混用两个阶段。

## 多类型工厂字段关联（证据包 2.7 / ProgramGraph 1.6 兼容保留）

`FactoryResult` 统一持有 `FactoryVariant`，不保留单类型工厂的并行实现。每种实际分配类型保存
自己的 return 位置和字段子槽位，直接创建、局部变量返回及有限工厂转发使用同一个公共算法。
同一 return 变量的 A/B 分支也能保留类型，不把 A 的受污字段传入 B 的同名敏感方法。
`ProgramCallSite.receiver_field_bindings` 只绑定已解析的兼容方法；抽象基类附加目标不冒充具体类型，
目标未解析或有未知副作用时仍诊断，不在安全层凭方法名补调用边。

类型化槽位是普通字段的子访问路径，父字段覆盖/整对象重绑定沿用公共到达定义规则；

普通字段直接读取保留可能值并集，方法读取则保持类型关联。`object_type_symbol` 连同分配、

## 核心语言高影响缺口补全

本轮优先补会中断常见 Source-to-Sink 路径、或错误扩散到安全值的功能，不以缺口数量为目标。

- Python：区分 `/`、`*`、`*args`、`**kwargs`；字面量序列/字典展开同时进入规则 IR 和程序图。
  args 的常量位置与 kwargs 的常量键分开，不把整个容器自动污染到安全兄弟成员。
- Java/Go：普通可变实参与直接打包数组/切片字面量共用 ParameterKind、BindingValue 和位置槽位。
  Java spread_parameter 的名字/类型读取由依赖语言之外的共享纯语法工具适配。
- Go：直接 return 的每个分量对应有序接收变量，不能把内容扩散到 error/安全分量；
  os.ReadFile/os.LookupEnv 的 Source 只选内容位置。CommandContext、SQL Context 和
  NewRequestWithContext 使用真实危险参数位置，规则版本为 go-core/1.1。
- C/C++：声明式输出参数经私有后置操作接入公共 CFG/DFG；返回状态码不是输入内容。
  read/fgets/fread/recv 等仅支持具名缓冲区和独立调用，保持 inferred/may、低置信度。
- 各核心语言：直接 `f(source())` 或精确关键字实参无需临时赋值；中间项目包装函数仍走
  已解析调用及实际返回路径。固定安全返回的包装函数不得把输入直接带到外侧 Sink。

这些适配不复制污点传播算法、不创建 calls 边、不修改原始持久化程序图。源码参数位置、
返回分量和声明类别是可选公共契约；旧数据缺省读取，但必须重新分析才能获得新证据。

未完成：通用嵌套调用结果/复杂表达式、动态容器展开、可变参数整集合传递、Go 裸命名返回及

这些缺口可能影响真实项目，不能统一称为影响有限；后续按实际使用与路径断点优先补。

   这属于有限静态运行库推断，不是完整编译器绑定或所有 JSX 运行库认证。
2. **常见传播桥接（已完成有限模型）**：React 表单→简单 useState setter→同组件状态读取；
   Node data→局部字符串/简单空数组累积→同请求 end。字符串使用公共 CFG 的退出值，
   保留分支、提前返回和确定安全覆写；数组仅支持直线 push。不是完整闭包、堆或事件循环分析。
3. **与实测有关的语义规则（后续）**：实际数据库/网络 API、必要调用目标和净化上下文修正。
   完整事件循环、全堆对象敏感、所有 npm 库、完整反射等暂缓；不因缺口数量多就全部实现。

Vue 事件写入由公共程序图标记为 inferred/may，而非把 HTML 标签顺序当执行顺序；
可能写入不杀死先前确定定义，模板读取与脚本 .value 使用同一 ref 身份。
安全证据及 LLM 端点保留 binding_certainty=may。模型仍须核实攻击者控制与实际执行条件。

## 工厂与组合引用边界（ProgramGraph 1.14）

共享快照导出已知返回可达对象，而非只匹配返回变量名；内部子对象、别名返回、共享引用和环使用
ObjectReferenceIndex 的同一状态，不新增语言私有污点引擎。工厂新分配按调用隔离；Python/Java/JS/TS
及 Go 已知局部对象用例覆盖内部组合返回，C/C++ 完整 new/构造列表等不因接口存在而称为已支持。

参数/接收者引用替换覆盖 Python、Java、JS/TS、Go/C/C++ 已适配的直接引用/指针字段；来源可为
已知实参、实参子路径或被调函数局部新对象，后者通过原值边界传输成员内容。实际外部对象保持原身份，
旧别名/其他共享组合不被一起替换。值参数不写回原对象；同对象多参数的原有拒绝仍保留。

局部效果→工厂导入→新可绑定调用逐轮衔接；同一次调用只编译一次，避免连续调用按旧拓扑绑定。
实际引用赋值位置与既有调用边进入证据和 ID 分页；并未向模型新增整份堆或依赖图输入。
指针修饰保存在原始字段类型中，规范化类型只服务于已有类名查找，避免将指针字段复制成内嵌值。

复杂引用/深层值混合副作用、未知调用、借用未绑定形参/全局对象的工厂关系、动态容器和完整并发仍是前沿。
