# 静态安全证据增强 A/B 实验协议

## 当前条件：v21 路径边界与独立评价

新按需条件为 `static-security-v21-chain-boundaries`，累计/完整源码条件为 v22/v23；共同报告 v7、台账 v2。保留 v20 的调查/报告额度及静态排序，新增明确起终点、局部/外部闭合范围、传播/部署/安全要求未知分类。局部区间不自动证明 HTTP 可达性，传播缺口强制 open。新人工评分分别记录发现广度、链路核验、结论可信度，无自动总分。引用检查按实际请求回执追溯早期批次，最终请求缺席不自动成为幻觉。源码脱敏保留语句结构，运行策略包含其版本。详细字段与边界见后端 `experiments/README.md`。本批条件包含共同报告与输入表示变化，不将效果变化单独归因于其中某一项；旧试次及人工评分不回填、不混算。

## 历史条件：v20 阶段隔离及独立报告预算

新按需试次为 `static-security-v20-isolated-report-stages`，批次规则为
`investigation-batches-v5-independent-report-stage`。模型、输出 Token、静态摘要 v5 及选择排序不变，继续无报告总字符上限。
两组共同 max_steps 仅约束调查模型请求（含收尾决策）；每批报告有独立一次主请求，最终另有一次汇总。
格式重提交仍整次至多一次，不占调查轮次，不因分批无限重试。主报告次数受批次推进约束且不超过调查请求上限。
调查工具定义去掉报告提交；批次报告只提供 submit_analysis_batch、选择 auto，允许单独提交或直接返回完整台账。
最终汇总无工具定义。每次调用都重建当轮 tools；服务端同时约束可执行工具，不能借未提供但已注册的名称越权。
最后两次调查提醒闭合现有链路，调查结束说明不是最终报告；预算耗尽仍会尝试当前批次的独立报告请求。
报告历史复用现有观察窗口预算，将工具结果投影为带 observation_id 的 APPLICATION_BATCH_EVIDENCE，
不携带旧 assistant 草稿、调用/参数包装或隐藏续接状态；完整源码、定位和省略标记继续保留。
预览状态仅依据本请求实际保留的投影，不提前标记交付；投影沿用既有路径记录和引用机械检查，不证明使用或语义正确。
请求 step 递增，调查另记 investigation_round，phase_requests 分开呈现应用发起的调查/报告/汇总/格式重提交，
不是 HTTP 次数或模型执行证明。各阶段与失败的真实用量仍累计，独立预算不意味着免费或调用次数两组必然相同。
原 .env 收尾值只作 configured_final_report_mode 审计；按需条件固定隔离策略，其他流程不变。
这是新的协议条件，需新建试次并与 v19 分开统计，不重写旧记录或凭旧日志补造新阶段。

## 历史条件：v19 取消批次报告总字符上限

新按需试次为 `static-security-v19-unbounded-batch-report`；批次规则为
`investigation-batches-v4-no-total-character-limit`，摘要仍为 `security-path-summary-v5-source-boundaries`。
唯一实验行为调整是删除批次 JSON、后台生成正文及提交工具 Schema 的 16000 总字符上限，
`batch_report_max_chars=null` 显式记录该条件，不代表未知；不裁掉已返回的台账来满足旧字符限制。
原模型、输出 Token 配置、调查轮次、收尾模式、路径选择/交付记录不变；不自动切换工具策略或重跑旧记录。
保留结构/状态/字段数量校验、响应完整性、输入保护、传输和审计安全配额。
没有应用批次总字符上限不等于模型平台容量无限，也不保证长报告能完整进入下一轮上下文。
两组使用相同条件，旧试次保留旧版本，不能与 v18 混算取消上限的效果。

## 历史条件：v18 来源与交付记录

新按需试次为 `static-security-v18-source-delivery`，摘要为 `security-path-summary-v5-source-boundaries`，
批次规则为 `investigation-batches-v3-explicit-limit`。沿用 v17 的路径族、12 轮默认值、工具权限和模型设置。
两组共同明确每批 JSON 与生成正文各自 16000 字符限制，不提高输出预算、自动截断或重跑失败记录。
新增旁路记录区分工具返回、真实 HTTP 发送尝试、收到响应/失败，以及模型请求/显式 ID 引用。
发送不等于接纳或使用，批次关联也不证明使用；文件引用机械检查不能证明某条路径影响了结论。
Source 保留识别类别及未知权限，不因管理员/配置来源删除观察；验收只对代表性正反例作结论。
静态算法、摘要及共同指令有变化，须重新分析、新建试次；不能与 v17 合并归因，旧记录不重写。

## 历史条件：v17 路径族

新按需试次为 `static-security-v17-path-families`，摘要版本 `security-path-summary-v4-groups`。
两组共同默认 12 轮、可选上限 36；族浏览只提供导航，不标记其内部路线已核验。
查看/报告具体路线才推进已处理集合；同族剩余路线继续可选，完整保留路径数不等于全图路径数。
独立第三方知识 Agent 未自动纳入任一实验组，不增加分析请求计数或静态事实。
未来纳入知识建议必须单独冻结条件、来源和成本，不能与本轮静态导航变更混算。
现有网络退避不变；没有加入新的上下文压缩。下面各版本为历史条件说明，旧记录保留原版本与轮次。

## 目标

比较同一个模型仅访问原始项目文件，与在相同文件访问能力基础上额外获得非 LLM 静态安全证据时的代码安全分析效果。新网页运行协议为 `static-security-v14-review-ledger`，当前报告版本 `ledger-security-v5`；累计配额与完整源码条件分别为 v15/v16。v5 从运行时台账模型生成完整 JSON Schema，替代 v4 不完整的手写形状示例；台账数据结构、导航、工具、轮次、预算及严格校验均不变。实验必须同时比较报告版本及契约哈希，不能仅按协议族合并 v4/v5。历史版本保留且不回填，不与新版本混算。本实验不预设证据组更优，持平、下降或提升都是有效研究结果；通信失败不是效果下降。

## 受控变量

两条通道接收相同问题、固定模型名、共同系统指令、Agent 步数与应用侧输入/输出预算。共同工具为 `list_project_files`、`read_file_range`、`search_project_text`、`search_project_text_many`、`submit_analysis_batch`；实验组另外有静态目录与按 ID 取详情工具，实际 Schema 分别冻结，并非完全相同。批量搜索共享一次遍历的扫描预算，不增加静态分析能力；返回扫描文件数、跳过原因、预算终止等范围信息。共享文件目录和只读访问策略；禁止使用 Manifest、符号索引、Repo Map、完整图和架构总结。运行期间不要修改项目源码、分析产物或服务端 Provider/预算配置。上传项目工作区按项目 ID 分离；这不是版本化数据集/不可变实验快照系统。

`security_evidence` 初始只接收公共选择器的 `security-path-summary-v2`：最多八条分级路径/线索，独立 UTF-8 上限 8000 字节，也保守满足调用方字符上限。默认已建模传播、结构调用线索、未建立传播的操作线索依次核验；同级先覆盖不同目标，再按显式 Shell 上下文和规则等级排序，不是漏洞概率。目录只带原 ID、端点、关系类型、优先理由、路径状态及必要省略计数；有余量展开全部原有步骤，长路径标记 detail_only，不抽样首尾。没有路径时不以孤立输入/条件填充，零条目不证明安全。目录不含源码、全局覆盖说明、Guard/Sanitizer 列表，不能算已读源码；覆盖/规则/全部局限另查 `_coverage`。同函数共现不是调用链，归为操作线索。按 ID 查询 overview、flow、snippets、protections、unresolved，组件完整分页，详情上限 24000 字符；大条目明确失败，不切碎 JSON。源码反向切片未实现。对照组不接收静态产物，两组原始文件工具和调查轮次不变。

v7 分批协议 `investigation-batches-v1`：默认共同 8 轮，可选 1～24；查询、读取、提交都消耗调查轮次，一轮可有多个读取，但提交报告必须单独调用。预算用尽至多追加当前批次报告与最终汇总两个禁止新工具的请求，按相同规则记录两组实际用量。不是强迫两组发出相同次数请求，也不保证按需成本更低。每批至多三个静态 ID，原始文件组用实际展示的路径＋行范围；同一文件其他范围可以继续调查。跨批重读共享实现是允许的，但同根因不能重复计数。

每批报告先保存为 `batch.completed` 并显示，再开始下一批；失败/取消保留此前报告，未完批次记为 `batch.pending`，不清除失败尝试成本。reported 只表示模型已形成报告，不表示漏洞已验证。新批次只保留共同指令、更新目录和报告台账，不混拼小对话的工具调用 ID 或推理续接项。最终以原报告台账和 `APPLICATION_BATCH_EVIDENCE` 汇总同根因；证据档案只含此前实际展示的完整观察，独立上限 12000 字符、按请求预算整体省略并标记数量。不能把模型报告升级为源码事实，不能补入之前未展示的完整工具正文冒充已核验。

历史 v18 及之前的按需批次单条最多 16000 字符，超过上限明确拒绝而不截断；当前 v19 已移除该总长度限制。当前恢复用于查看报告和未完状态，不新增断点续跑接口；新的配对重新调查，不继承旧运行排除集合。基础完成率、有效配对质量、所有尝试成本分别报告；调查闭合与三维确认状态仍需人工核对，不能按问题数或模型自标“已确认”评分。相关入口见 `backend/app/experiments/README.md`；MCP、skill 加载器、向量数据库均未引入。

执行入队顺序和左右展示顺序独立随机化，两个运行、队列项与配对记录在同一数据库事务中创建，失败整体回滚。默认单 Worker 顺序消费；多个 Worker 时可能同时执行，`execution_order` 仅表示入队顺序，不保证实际启动/完成顺序。严谨的延迟实验建议使用单 Worker，并保持运行环境稳定。

创建前先预检两组上下文，不满足预算则返回明确错误，不创建只剩一组有效的模型任务。只有两组均 `completed` 且回答完整性检查通过才能盲评。`failed/cancelled`、长度终止或完整性未知的配对可以显示和审计，但 `valid_for_review=false`，不能作为效果试次评分；不能只因截断组输赢选择性补跑。不得用确定性静态回退冒充模型实验。评分记录正确性、完整性、证据充分性、幻觉控制、偏好和备注，提交后才允许揭盲。答案中可能显露静态证据来源，因此这里是“隐藏组别标签”，不保证评审者完全无法猜测组别。

v4 的共同阶段协议是 `explicit-report-phases-v1`：每轮提供调查阶段与剩余工具轮次（含本轮）；最终阶段禁止新调查，按已有、实际展示的证据报告未核实链路和局限。阶段消息本身不属于安全证据，并计入完整请求预算。默认仍为 4 轮调查 + 1 次报告，不因失败自动增轮。

v5 保留该阶段协议，增加 `security_evidence_schema=1.4` 到冻结的共同策略：同页共享片段表避免把一个资源在多条候选中重复展开。资源角色、位置、正文、截断信息与候选关联完整保留；不合并不同路径，也不把候选数当作漏洞数。预算直接按共享 JSON 计算，压缩观察时引用与正文作为闭包选择，仍遵守省略说明。格式变化或预算内可容纳候选数量变化应作为新条件，不与旧格式试次混算；没有提高调查轮次或给对照组新增静态能力。

最终模式由 `CODE_EXPLORER_LLM_FINAL_REPORT_MODE` 显式设置并记录审计与指标：`tools_none` 保留定义且发送 `tool_choice=none`；`history_no_tools` 省略工具定义及工具选择字段，但保留有效配对历史。两组模式、轮次与阶段版本必须一致；创建配对时冻结契约，Worker 不得暗中切换。固定兼容性用例 `test/probe_final_report_modes.py --send` 每模式只请求一次，不用真实项目，不能证明大上下文兼容性。若之后使用 6 轮或改变证据预算，应作为不同条件新建试次并单独统计，不修改失败试次。

两组最终输出同一完整 JSON 台账，由 `experiments/findings.py` 验证后确定性生成四段 Markdown：`结论`、`已核实问题`、`未确认风险`、`范围与局限`。摘要最多突出五项源码支持风险，其他独立根因仍全列；不由模型另写摘要编号或计数。模型原始 JSON 在可见消息审计中保留，运行答案是由台账生成的 Markdown，旧 Markdown 答案不重建。生成的结束标记仅用于结构检查，语义覆盖始终为 `not_proven`。

### 发现台账与共同覆盖（v14/v15/v16）

每项保存独立根因、行为和 observed/inferred/unknown 状态、输入到真实危险实现的 closed/open/not_applicable 链路、
防护的值对应/上下文/先后顺序、安全影响 established/conditional/not_established、已知及未满足/未知利用条件、精确引用和状态。
状态仅三类：`source_supported_risk`、`unclosed_candidate`、`excluded`。源码支持风险须观察到行为、链路闭合或明确不适用，
且影响已建立或有明示条件；它不等于已确认远程漏洞。排除项须给理由，不可凭未找到调用方排除全项目风险。
条件影响必须列出未满足或未知条件，完全同文字根因重复会拒绝，但不假装能自动识别所有语义重复。

两组必填六类覆盖：输入边界、认证授权、资源限制、错误处理、敏感操作、输出上下文。
每类为已检查/未检查/不适用，附范围理由；已检查及不适用必须有源码引用。
不是答案清单，不强迫每类报漏洞，也不把部分已读范围推广到全仓库已审计。

`submit_analysis_batch(ledger_json, evidence_ids, scopes)` 仍是两组共同工具，不增加请求或轮次。
批次事件保留原台账及生成报告，下一批只带台账、不重复带 Markdown；最终合并仍由模型完成，后台不自动语义合并或提高状态。
结构/状态冲突明确失败并保留原始响应和用量，不修复 JSON、不补字段、不暗中退回旧自由报告、不追加重生成。
源码引用的存在和展示范围沿用机械审计；合法引用不证明其支持断言。普通项目问答不强制采用实验台账。
本轮未改导航排序、摘要预算、调查轮次、静态规则或传播算法，未自动创建真实实验。

v11 直接替换旧摘要，不并行维护零散事实/实现组初始选择；v7、v9、v10 的既有结果继续原样读取。累计预算诊断默认改为 `static-security-v12-cumulative-paths`，复用同一个选择器，静态正文仍按实际字节占用共同额度。`legacy-facts-v1` 仅用于显式历史 v9 条件，不是网页默认。显式详细查询的 1.4 格式仍可返回未配对 Source/Sink 等原始观察，但不再作为初始摘要。规则覆盖表示启用匹配器，不表示框架存在或完整覆盖；零入口不等于无外部输入，零候选不等于无漏洞。

## 指标解释

输出预算分为“显式有限上限”和“省略参数、使用平台默认”两种条件。环境变量未配置默认 2400，显式留空才省略实际请求输出字段；不能发送 `null`，也不能把平台默认称为无限输出。空值模式通过 `CODE_EXPLORER_LLM_OUTPUT_RESERVE_TOKENS` 保留本地输入规划空间，但该值不限制实际输出、不发送给模型，也不保证未知输出能放进窗口。

新审计与指标记录 `output_limit_mode`、`output_reserve_tokens`、`output_reserve_basis`；空值模式使用预算版本 `utf8-token-budget-v3-provider-default`，有限模式仍为 v2。两组必须使用相同模式和预留值；改变任一项必须新建条件，不能补跑单侧拼接旧配对。历史缺失字段保持未知，不重写旧记录。省略输出上限不放宽报告完整性检查，也不改变超时、重试或提示词。

- `duration_ms`：`run.started` 到终态事件的实际分析耗时，不包含排队；`queue_duration_ms` 单独记录。
- `adjusted_duration_ms`：仅新审计下，墙钟耗时扣除已确认执行前拒绝请求及其实际退避时间；`excluded_network_ms` 单列剔除量。不是纯模型计算时间，成功请求仍包含传输与平台等待。未知拒绝计时或历史缺失时不伪造调整值。
- 输入估算：新记录累计每轮完整请求 JSON 的 UTF-8 字节保守估算，包含指令、工具 Schema、问题、证据、会话及工具预算耗尽后的最终请求；旧记录仍明确标记历史字符数除以 4 的近似值。
- `max_request_input_estimate`：各轮最大单次请求的输入估算；累计值是多轮之和，不能用于判断单次是否超窗。
- 输出估算：新记录累计可见文本与规范化工具调用的 UTF-8 字节估算；旧记录缺少字节数时采用字符近似，缺少响应事件时返回空值。
- 以上不是 tokenizer 精确结果，不包含隐藏推理，也不是供应商账单 usage；不能用于精确费用结论。
- `actual_input_tokens/actual_output_tokens/actual_total_tokens`：累计供应商真实返回的每轮 usage；`usage_status=complete/partial/unavailable` 区分全部、部分和完全未知。部分和缺失不替换为估算；缓存/推理细分计数不重复加到总量。返回 usage 不等于已经核对供应商账单。
- `finish_reasons`：每轮上游终止原因；`termination_reason`：Agent 因模型给出最终答案或工具轮次耗尽而结束。`answer_completeness` 独立描述传输和报告结构；`completed` 状态自身不保证答案完整。
- `observation_compactions/max_omitted_observations`：工具正文压缩次数和单窗口最多省略的观察数。完整结果留在事件中，模型只接收合法 JSON 和完整源码行；省略条目可审计，不代表模型已读取全部持久化证据。
- `observation_window_version`：工具窗口的实现版本。当前 `native-tool-rounds-v2` 保持原生调用/结果整轮配对并保障最新可用正文；旧字符串窗口实现已经删除。两组版本不同或实际返回模型不同不可正式同条件评分。旧字段缺失不回填，不能把窗口升级前的对照答案当作升级后的同条件对照。
- `evidence_count`：最终按 path/line/symbol 去重的初始证据与工具证据，不是漏洞数、模型引用数或答案正确性。证据组天然可能有更多初始条目，另提供 `initial_evidence_count`、`tool_evidence_count` 和 `model_requests`。

## 如何做有效性实验

报告产出稳定性与分析质量分开统计：按同项目/问题、源码与产物指纹、提示词/工具契约、模型、调查轮次、报告模式和预算划分条件；分别列出可见正文产出、正常传输终止及报告契约完成率，分母包含该条件下全部试次。不同输出预算、报告模式或静态证据预算不得混算，也不得把一次失败配对的单侧补跑与原成功侧拼接。当前报告结束标记仍是冻结契约的一部分；不能因为某一侧正文质量看起来较好就事后放宽或补写。

质量只在完整有效配对上采用同一人工核验标准：每个独立根因分别检查源码行为、影响链与利用前提，记录直接源码位置、反证、条件和未知部署因素；模型自标“已核实”不是真值。人工核验材料不进入模型上下文，不改原回答或盲评记录。单样本核验中发现的问题不立即改成样本专属提示词。

成本表保留全部尝试并避免重复累计。默认未知失败不补零；唯一例外是管理员明确绑定当前供应商/端点/模型指纹，声明该平台 429/503 为执行前拒绝。声明进入两组冻结策略及审计，记录 `assumed_zero_token_attempts`，不改供应商 usage 或原 `usage_status`。另列 `accounted_usage_status`、`accounted_model_total_tokens` 和仍未知成本的尝试数；这是按已确认平台行为核算模型 Token，不是伪造供应商账单。切换端点/模型后声明失效；socket 超时、连接中断、其他状态和本地解析失败不自动归零。历史不回填，无平台价格不估算金额，旧试次及网络失败不删除。

先执行 `docs/FUNCTIONAL_VALIDATION.md` 的功能验证，再选择带人工真值的漏洞样例、已修复对照和真实项目。固定问题、项目版本、模型、参数和预算，每个项目/问题做多次配对并记录随机波动；两组接受同一人工核验标准。重点检查真实漏洞命中、误报、遗漏、引用位置、攻击者控制条件和证据覆盖，而非仅比较耗时/Token/工具数。报告所有合法试次，不因某组输赢挑选结果。

当前不包含自动真值评分、前端重复试次统计、置信区间或部署环境全量快照；已有项目历史列表、原始提示词/条件比较和已保存盲评结果显示。旧 `test/run_security_retest.py` 自建编排已经删除，当前补充实验由 `experiments.full_source_trial` / `experiments.cumulative_trial` 复用持久化 Worker 和统一审计。旧试次仍完整保留。资源预算改变后必须作为新协议条件记录，不能混算为严格同条件试验。这些限制不妨碍原型配对试验，但需要在研究报告中说明。Rust 尚无安全规则；没有候选不能解释为“安全”。

## 台账语义待核验事项（2026-10-19，不改变当前实验契约）

极小样本配对 `a3580733adc94801afb7ded7605772cd` 的人工复核提出下列问题。先记录，后续结合 audio2sheet 新配对检查，不据此立即修改提示词、状态校验、选择器或旧报告；这些核验事项不进入本轮模型上下文。

1. **风险状态不等于真实漏洞。** `source_supported_risk` 目前允许已观察行为、闭合或不适用链路及有条件影响。应在人工评价中区分“缺陷机制明确、利用依赖部署条件”与“是否违反业务或授权要求本身仍未知”的观察。缺少应用内认证不能单独证明公开文档服务存在漏洞，模型状态计数不可直接作为准确率分子。

3. **合法引用不能证明断言成立。** 按已知或可猜测文件名读取文件，不自动推出可枚举全部文件名或读取目录内全部文件。核验仍需逐项比对行为与源码，不因机械引用通过而认可扩大的攻击能力。
4. **防护统计可能漏记安全调用形式。** 排除依据可能散落在 `behavior`、`confirmed_conditions`、`exclusion_reason` 中，`protections=[]` 不必然表示未核实防护。人工复核同时记录安全 API/参数形式与显式校验，检查实际值、危险上下文和执行时序；暂不修改原始台账字段。
5. **覆盖声明不是发现完整性证明。** 六类 `checked` 仅表示模型声明检查并提供引用，不能证明独立问题全部被发现、根因正确拆分或候选升级/排除正确。保留 `semantic_coverage=not_proven`，人工核验遗漏、合并及结论边界。
