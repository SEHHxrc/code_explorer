# 静态安全证据增强 A/B 实验协议

## 目标

比较同一个模型仅访问原始项目文件，与在相同文件访问能力基础上额外获得非 LLM 静态安全证据时的代码安全分析效果。协议标识为 `static-security-v1`。本实验不预设证据组更优，持平、下降或提升都是有效研究结果；通信失败不是效果下降。

## 受控变量

两条通道接收相同问题、固定模型名、共同系统指令、Agent 步数与应用侧字符/输出预算。两组的工具 Schema 和权限完全相同：`list_project_files`、`read_file_range`、`search_project_text`。共享文件目录和只读访问策略；禁止使用 Manifest、符号索引、Repo Map、完整图和架构总结。运行期间不要修改项目源码、分析产物或服务端 Provider/预算配置。上传项目工作区按项目 ID 分离；这不是版本化数据集/不可变实验快照系统。

`security_evidence` 通道额外接收 `SecurityEvidencePromptBuilder` 构造的紧凑 JSON：Source/Sink、规则与 CWE、候选结构/值流路径、代码片段、Guard/Sanitizer、源码位置、置信度、攻击者控制前提和覆盖缺口。超预算时整条省略并报告数量，不截断 JSON。完整依赖图仅用于展示与服务器内部路径计算，系统生成启动建议不进入实验。对照组 `baseline` 不接收任何静态分析产物。

执行入队顺序和左右展示顺序独立随机化，两个运行、队列项与配对记录在同一数据库事务中创建，失败整体回滚。默认单 Worker 顺序消费；多个 Worker 时可能同时执行，`execution_order` 仅表示入队顺序，不保证实际启动/完成顺序。严谨的延迟实验建议使用单 Worker，并保持运行环境稳定。

只有两组均 `completed` 才能盲评。`failed/cancelled` 的配对可以显示和审计，但 `valid_for_review=false`，不能作为效果试次评分。不得用确定性静态回退冒充模型实验。评分记录正确性、完整性、证据充分性、幻觉控制、偏好和备注，提交后才允许揭盲。答案中可能显露静态证据来源，因此这里是“隐藏组别标签”，不保证评审者完全无法猜测组别。

## 指标解释

- `duration_ms`：`run.started` 到终态事件的实际分析耗时，不包含排队；`queue_duration_ms` 单独记录。
- 输入估算：累计每轮规范化请求的指令、工具 Schema、问题、证据和工具观察字符数除以 4，包含工具预算耗尽后的最终请求。
- 输出估算：累计各轮文本与规范化工具调用参数字符数除以 4。旧运行缺少响应事件时返回空值。
- 以上不是 tokenizer 精确结果，不包含隐藏推理，也不是供应商账单 usage；不能用于精确费用结论。
- `evidence_count`：最终按 path/line/symbol 去重的初始证据与工具证据，不是漏洞数、模型引用数或答案正确性。证据组天然可能有更多初始条目，另提供 `initial_evidence_count`、`tool_evidence_count` 和 `model_requests`。

## 如何做有效性实验

先执行 `docs/FUNCTIONAL_VALIDATION.md` 的功能验证，再选择带人工真值的漏洞样例、已修复对照和真实项目。固定问题、项目版本、模型、参数和预算，每个项目/问题做多次配对并记录随机波动；两组接受同一人工核验标准。重点检查真实漏洞命中、误报、遗漏、引用位置、攻击者控制条件和证据覆盖，而非仅比较耗时/Token/工具数。报告所有合法试次，不因某组输赢挑选结果。

当前不包含自动真值评分、重复试次汇总、置信区间、参数全量快照或实验历史列表 UI；历史配对及评分保存在数据库，可通过已知比较 ID 查询。这些限制不妨碍原型配对试验，但需要在研究报告中说明。Rust 尚无安全规则；没有候选不能解释为“安全”。

旧 `graph` 协议历史保留但标为 `legacy-graph`，不能与新协议混合统计；旧待执行图任务拒绝续跑。数据库 `graph_run_id` 保留历史列名，新配对由 `execution_order` 的 `security_evidence` 标识真正策略，避免隐式破坏用户数据。

## 临时对照组删除清单

如果重复实验确认静态安全证据通道更优，并决定结束对照实验，先导出结果，再定位边界标记：

```powershell
rg -n "TEMPORARY CONTROL GROUP|临时对照组" backend frontend test docs
```

然后：

1. 删除 `backend/app/experiments/baseline/`。
2. 删除 `agents/worker.py` 的 baseline 分支及实验配对中的对照运行创建逻辑。
3. 如果不再保留历史实验记录，通过显式数据库迁移移除 `baseline_run_id` 和盲态比较持久化字段。
4. 如果实验工作整体结束，而不是更换另一种对照，则删除比较 API/路由、比较界面和 `frontend/src/services/experimentApi.js`。
5. 将隔离与功能链路测试调整为只验证正式证据路径。
6. 保留静态安全证据生产与正式 Agent 能力。普通 `/api/agent` 不直接导入临时对照包。

如需历史分析，应在删除表之前导出实验结果。从 Git 删除的源文件仍可通过仓库历史恢复。
