# 静态安全证据增强 A/B 实验协议

## 目标

比较同一个模型仅访问原始项目文件，与在相同文件访问能力基础上额外获得非 LLM 静态安全证据时的代码安全分析效果。新运行协议标识为 `static-security-v5`，报告版本为 `concise-security-v2`；历史版本保留且不回填，不与新版本混算。本实验不预设证据组更优，持平、下降或提升都是有效研究结果；通信失败不是效果下降。

## 受控变量

两条通道接收相同问题、固定模型名、共同系统指令、Agent 步数与应用侧输入/输出预算。两组的工具 Schema 和权限完全相同：`list_project_files`、`read_file_range`、`search_project_text`、`search_project_text_many`。批量搜索共享一次遍历的扫描预算，不增加静态分析能力；返回扫描文件数、跳过原因、预算终止等范围信息。共享文件目录和只读访问策略；禁止使用 Manifest、符号索引、Repo Map、完整图和架构总结。运行期间不要修改项目源码、分析产物或服务端 Provider/预算配置。上传项目工作区按项目 ID 分离；这不是版本化数据集/不可变实验快照系统。

`security_evidence` 通道额外接收 `SecurityEvidencePromptBuilder` 构造的紧凑 JSON：Source/Sink、规则与 CWE、候选结构/值流路径、代码片段、Guard/Sanitizer、源码位置、置信度、攻击者控制前提和覆盖缺口。超预算时整条省略并报告数量，不截断 JSON。完整依赖图仅用于展示与服务器内部路径计算，系统生成启动建议不进入实验。对照组 `baseline` 不接收任何静态分析产物。

执行入队顺序和左右展示顺序独立随机化，两个运行、队列项与配对记录在同一数据库事务中创建，失败整体回滚。默认单 Worker 顺序消费；多个 Worker 时可能同时执行，`execution_order` 仅表示入队顺序，不保证实际启动/完成顺序。严谨的延迟实验建议使用单 Worker，并保持运行环境稳定。

创建前先预检两组上下文，不满足预算则返回明确错误，不创建只剩一组有效的模型任务。只有两组均 `completed` 且回答完整性检查通过才能盲评。`failed/cancelled`、长度终止或完整性未知的配对可以显示和审计，但 `valid_for_review=false`，不能作为效果试次评分；不能只因截断组输赢选择性补跑。不得用确定性静态回退冒充模型实验。评分记录正确性、完整性、证据充分性、幻觉控制、偏好和备注，提交后才允许揭盲。答案中可能显露静态证据来源，因此这里是“隐藏组别标签”，不保证评审者完全无法猜测组别。

v4 的共同阶段协议是 `explicit-report-phases-v1`：每轮提供调查阶段与剩余工具轮次（含本轮）；最终阶段禁止新调查，按已有、实际展示的证据报告未核实链路和局限。阶段消息本身不属于安全证据，并计入完整请求预算。默认仍为 4 轮调查 + 1 次报告，不因失败自动增轮。

v5 保留该阶段协议，增加 `security_evidence_schema=1.4` 到冻结的共同策略：同页共享片段表避免把一个资源在多条候选中重复展开。资源角色、位置、正文、截断信息与候选关联完整保留；不合并不同路径，也不把候选数当作漏洞数。预算直接按共享 JSON 计算，压缩观察时引用与正文作为闭包选择，仍遵守省略说明。格式变化或预算内可容纳候选数量变化应作为新条件，不与旧格式试次混算；没有提高调查轮次或给对照组新增静态能力。

最终模式由 `CODE_EXPLORER_LLM_FINAL_REPORT_MODE` 显式设置并记录审计与指标：`tools_none` 保留定义且发送 `tool_choice=none`；`history_no_tools` 省略工具定义及工具选择字段，但保留有效配对历史。两组模式、轮次与阶段版本必须一致；创建配对时冻结契约，Worker 不得暗中切换。固定兼容性用例 `test/probe_final_report_modes.py --send` 每模式只请求一次，不用真实项目，不能证明大上下文兼容性。若之后使用 6 轮或改变证据预算，应作为不同条件新建试次并单独统计，不修改失败试次。

两组共享四段简洁报告：`结论`、`已核实问题`、`未确认风险`、`范围与局限`。仅摘要最多突出五个问题，其余有证据的独立根因仍须简列，评分依据去重后的问题清单。每项分别说明代码行为、安全影响与利用前提，不因未知部署条件否定源码事实，也不直接把本地异常升级为远程漏洞。共同指令要求核对引用、区分触发条件，并将未测试等内容放在局限，不加入样本专属答案清单。要求结束标记 `<!-- SECURITY_REPORT_END -->`；前端隐藏标记，但持久化原回答不改写。检查区分传输正常结束、报告结构齐全和安全分析的语义覆盖；后者始终标记 `not_proven`，结束标记不是完成全部审计的证明。

无候选时，证据组仍接收实际入口、未配对 Source/Sink 及可用的精确源码位置和片段，而不是只有统计。小预算优先位置、再分配片段；所有省略均报告。规则覆盖表示启用匹配器及类别，不表示框架确实存在或所有语义均支持；零入口不能推出无外部输入，零候选不能推出无漏洞。

## 指标解释

输出预算分为“显式有限上限”和“省略参数、使用平台默认”两种条件。环境变量未配置默认 2400，显式留空才省略实际请求输出字段；不能发送 `null`，也不能把平台默认称为无限输出。空值模式通过 `CODE_EXPLORER_LLM_OUTPUT_RESERVE_TOKENS` 保留本地输入规划空间，但该值不限制实际输出、不发送给模型，也不保证未知输出能放进窗口。

新审计与指标记录 `output_limit_mode`、`output_reserve_tokens`、`output_reserve_basis`；空值模式使用预算版本 `utf8-token-budget-v3-provider-default`，有限模式仍为 v2。两组必须使用相同模式和预留值；改变任一项必须新建条件，不能补跑单侧拼接旧配对。历史缺失字段保持未知，不重写旧记录。省略输出上限不放宽报告完整性检查，也不改变超时、重试或提示词。

- `duration_ms`：`run.started` 到终态事件的实际分析耗时，不包含排队；`queue_duration_ms` 单独记录。
- 输入估算：新记录累计每轮完整请求 JSON 的 UTF-8 字节保守估算，包含指令、工具 Schema、问题、证据、会话及工具预算耗尽后的最终请求；旧记录仍明确标记历史字符数除以 4 的近似值。
- `max_request_input_estimate`：各轮最大单次请求的输入估算；累计值是多轮之和，不能用于判断单次是否超窗。
- 输出估算：新记录累计可见文本与规范化工具调用的 UTF-8 字节估算；旧记录缺少字节数时采用字符近似，缺少响应事件时返回空值。
- 以上不是 tokenizer 精确结果，不包含隐藏推理，也不是供应商账单 usage；不能用于精确费用结论。
- `actual_input_tokens/actual_output_tokens/actual_total_tokens`：累计供应商真实返回的每轮 usage；`usage_status=complete/partial/unavailable` 区分全部、部分和完全未知。部分和缺失不替换为估算；缓存/推理细分计数不重复加到总量。返回 usage 不等于已经核对供应商账单。
- `finish_reasons`：每轮上游终止原因；`termination_reason`：Agent 因模型给出最终答案或工具轮次耗尽而结束。`answer_completeness` 独立描述传输和报告结构；`completed` 状态自身不保证答案完整。
- `observation_compactions/max_omitted_observations`：工具正文压缩次数和单窗口最多省略的观察数。完整结果留在事件中，模型只接收合法 JSON 和完整源码行；省略条目可审计，不代表模型已读取全部持久化证据。
- `observation_window_version`：工具窗口的实现版本。当前 `complete-records-v2` 保障最新可用正文和完整目录/匹配条目；两组版本不同或实际返回模型不同不可正式同条件评分。旧字段缺失不回填，不能把窗口升级前的对照答案当作升级后的同条件对照。
- `evidence_count`：最终按 path/line/symbol 去重的初始证据与工具证据，不是漏洞数、模型引用数或答案正确性。证据组天然可能有更多初始条目，另提供 `initial_evidence_count`、`tool_evidence_count` 和 `model_requests`。

## 如何做有效性实验

报告产出稳定性与分析质量分开统计：按同项目/问题、源码与产物指纹、提示词/工具契约、模型、调查轮次、报告模式和预算划分条件；分别列出可见正文产出、正常传输终止及报告契约完成率，分母包含该条件下全部试次。不同输出预算、报告模式或静态证据预算不得混算，也不得把一次失败配对的单侧补跑与原成功侧拼接。当前报告结束标记仍是冻结契约的一部分；不能因为某一侧正文质量看起来较好就事后放宽或补写。

质量只在完整有效配对上采用同一人工核验标准：每个独立根因分别检查源码行为、影响链与利用前提，记录直接源码位置、反证、条件和未知部署因素；模型自标“已核实”不是真值。人工核验材料不进入模型上下文，不改原回答或盲评记录。单样本核验中发现的问题不立即改成样本专属提示词。

成本表保留成功、失败、截断、契约缺失、网络重试及参数探测；参数探测开销单列。优先核对每个HTTP响应的usage，避免与同一响应的Agent事件重复累计。超时/失败尝试没有usage时保持未知，已报告合计只是可观察用量，不能当作全部账单或补零；无平台价格则不估算金额。预算诊断存于独立数据库，也必须登记到研究台账，不能只导出正式数据库中的成功样本。协议/参数改变后的试次另建条件，不抹除原试次。

先执行 `docs/FUNCTIONAL_VALIDATION.md` 的功能验证，再选择带人工真值的漏洞样例、已修复对照和真实项目。固定问题、项目版本、模型、参数和预算，每个项目/问题做多次配对并记录随机波动；两组接受同一人工核验标准。重点检查真实漏洞命中、误报、遗漏、引用位置、攻击者控制条件和证据覆盖，而非仅比较耗时/Token/工具数。报告所有合法试次，不因某组输赢挑选结果。

当前不包含自动真值评分、前端重复试次统计、置信区间、部署环境全量快照或实验历史列表 UI；历史配对及评分保存在数据库，可通过已知比较 ID 查询。`test/run_security_retest.py` 是显式授权才执行的真实测试脚本，在新建数据库、工作区和产物目录保存配对汇总、完整事件、配置预算及输入哈希，拒绝覆盖已有结果目录；它不自动重试不完整答案或删除失败样本。资源预算改变后必须作为新协议条件记录，不能混算为严格同条件试验。这些限制不妨碍原型配对试验，但需要在研究报告中说明。Rust 尚无安全规则；没有候选不能解释为“安全”。

## 可见消息审计与引用警告

新配对按相同配额收集脱敏后的实际请求消息、工具定义/参数、每次 HTTP 尝试及可见回复、结束原因、usage，保存共同指令版本/哈希及运行时源码/静态产物内容哈希。发送规划与实发记录分开；API 与 Worker 的契约不一致时不发送请求。API Key、认证头及隐藏推理/加密状态不保存。审计正文不进入普通 SSE，也不会成为对照组的模型输入。配额、过期、已盲评保护和项目删除事务详见 [审计模块](../backend/app/experiments/audit/README.md)。

引用检查只核对快照中的相对路径、有效行号以及实际请求中的源码展示范围，不把定位条目或未展示正文的占位提示算成源码。警告展示给评审者，但不自动排除不正确答案或证明结论正确，`semantic_coverage=not_proven` 保持不变。完整审计默认禁止网页读取；本机管理员通过独立口令显式访问，有效实验需先盲评，无效终态实验需显式确认诊断揭盲。旧实验不补写。

旧 `graph` 协议历史保留但标为 `legacy-graph`，不能与新协议混合统计；旧待执行图任务拒绝续跑。数据库 `graph_run_id` 保留历史列名，新配对由 `execution_order` 的 `security_evidence` 标识真正策略，避免隐式破坏用户数据。

## 临时对照组删除清单

如果重复实验确认静态安全证据通道更优，并决定结束对照实验，先导出结果，再定位边界标记：

```powershell
rg -n "TEMPORARY CONTROL GROUP|临时对照组" backend frontend test docs
```

然后：

1. 删除 `backend/app/experiments/baseline/`。
2. 删除 `agents/worker.py` 的 baseline 分支及实验配对中的对照运行创建逻辑。
3. 如果不再保留历史实验记录，通过显式数据库迁移移除 `baseline_run_id` 和盲态比较持久化字段。
4. 如果实验工作整体结束，而不是更换另一种对照，则删除比较 API/路由、比较界面和 `frontend/src/services/experimentApi.js`。
5. 将隔离与功能链路测试调整为只验证正式证据路径。
6. 保留静态安全证据生产与正式 Agent 能力。普通 `/api/agent` 不直接导入临时对照包。

如需历史分析，应在删除表之前导出实验结果。从 Git 删除的源文件仍可通过仓库历史恢复。
