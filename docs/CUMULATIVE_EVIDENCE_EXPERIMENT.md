## 累计配额语义

两组有相同的 `read_file_range` 和 `search_project_text_many` 工具、8 轮调查、现有最终报告模式与输出配置。
固定文件清单、工具定义、共同指令和包装不计入**本地累计证据配额**，但仍可能消耗真实输入 Token。
静态事实紧凑 JSON 正文首次计费；首次输出某文件某行时按该完整原行含换行计费。
重复读取或再次搜索到同一行免费；两个不同文件的相同行不当成同一证据。
搜索也是原始文件字面搜索，不提供 AST 或静态索引；命中正文同样计费，不能用搜索绕过限制。
读取每次最多 200 行，预算不足时在完整行边界停止并返回 `next_start_line`，不硬截断源码行。
本轮不分批、不额外提供静态详情工具，不执行目标项目。

配额按**工具结果分配**，实际展示范围另外从收到响应的真实请求重建。
最后一轮返回但未发送给模型的工具内容不能算已读。
理论可读完不表示模型一定选择了全部文件；必须同时报告实际唯一展示行/字节和未读取范围。
重复附带历史、模型输出和推理的成本不由此配额限制，按供应商真实 usage 另行汇总。

### 非盲态辅助内容复核

以下是根据源码与实际展示范围的辅助核对，不是独立人工盲评，不自动提交偏好或分数，也不是穷尽真值。

- **AES A**：静态组指出 `AES.py:186-188` 的实际逻辑错误：初始化轮密钥列表仅含 4/6/8 个元素，
  循环却从密钥字节数 16/24/32 起步，首次访问 `self.__keys[i-1]` 越界。原始组未指出该点。
  这是默认 ECB 构造路径上的可确认功能缺陷，不直接算新增远程安全漏洞。
  原始组核实了另一实现 `AES_showDatas.py` 的长度/IV 处理；静态组主体未整读，不能对该实现作同等判断。
  静态组还错误地将包含 `input()`/`import` 命中的搜索描述成全部零命中；不得采纳其绝对排除措辞。
- **AES B**：两组均报告 ECB、填充、assert/exit 与 CLI 输入健壮性等相近类别，没有核实上述密钥扩展错误。
  静态组读取更少、用量更低，但不能因风险清单相似就认定覆盖相同。
  原始组关于“知道一段 OFB 明文即可推导后续密钥流”的表述缺乏依据；不能把已知位置的密钥流恢复
  等同于能够预测未覆盖位置的密钥流。两组也有把健壮性与假设部署影响混写的情况。
- **audio2sheet B**：两组均追到 Spleeter 的实际 `shell=True` 调用与 HTTP 参数，说明 Windows/POSIX 差异和
  网络暴露等前提；均识别转谱路径构造问题，区分下载端 `commonpath` 不保护转谱路径。
  原始组实际读取 `basic_pitch_impl.py:33-63`，能以建目录、删除、rename 等源码核实具体文件操作。
  静态组仅通过搜索看到该文件第 62 行的删除调用，未读建目录与 rename 的上下文；却主要依赖
  MT3 的外部 exe 参数传播推断最终写入，相关执行语义仍有缺口；
  不能仅因报告写“已确认”就当成与原始组同等闭合的链路。
  静态组准确区分了 `safe_id` 的清洗与 `url` 的未核实关系，没有把前者当成后者的防护；
  通过搜索到的静态调用参数排除了 `render_empty` 用户输入候选，而原始组保留了该缺口。
  两组仍将认证、上传限制等不同根因合并；静态组关于“无限并发”“同步触发”的强表述，不能由
  源码中无业务配额直接推出，实际执行器/代理层资源限制未审查。
- **引用核对**：AES 两个静态报告的未展示源码警告发生在其明确列为未读的段落，不能自动判成虚构引用；
  audio2sheet B 原始组有 1 处、静态组有 5 处合并坐标语法警告。格式、已展示范围与断言支持性是不同维度。
  机械检查通过仍不证明代码支持断言。audio2sheet A 整对不进入正式质量比较。

### 能得出的结论与下一步边界

本次验证了两种累计资源条件可运行，且模型不需要读完全文也可能定位主要安全相关代码。
当前静态事实输入没有显示稳定的质量或成本优势；也有局部核实差异，不能据此证明静态分析无用。
每项目每条件只有一对、仅两个 Python 项目，且复核非盲态，不能做显著性或普遍性结论。
保持已有生产协议不变，不把 v9 与此前 v7/v8 合并排名，不按本轮输赢改提示词。

若继续研究，优先单独测试静态选择是否真正保留危险实现与最小路径：当前固定排序填满 facts 后，
候选关联没有保留下来，尤其 audio2sheet 丢弃了 11 条关联。
先设计并冻结新选择条件，再重复配对；不要将本次已成功的片段去重重新列为待修复项，
也不要把静态输入预算、调查轮次、报告完成机制同时改变后归因于其中一项。
